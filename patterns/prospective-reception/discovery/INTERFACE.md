# Turn CLI reference

`python -B turn.py STATE ACTION SPEC.json` prints a compact JSON record, including its content-addressed `id`. Store the operator's SQLite state outside the release. Fields below are required unless described as optional.

| Action | Fields |
|---|---|
| `open` | `target`, `gap`, `prediction`, `rival`, `partial`, `query` |
| `lookup` | `prospect` (open ID), `reader` (trusted native `knowledge.py` path). Optional `library`, `scan_limit`, `max_bytes` and the pair `index`, `index_sha256`. |
| `issue` | `prospect`, `sources`, `uses`. Optional `nominations` (same prospect's lookup ID). For an already known source one may instead supply `target`, `gap`, `prediction`, `rival`, `partial` in place of `prospect`. Both forms optionally accept `parent` (observation ID), `relation` (`reuse`, `reopen`, `split`) and `because` together. |
| `observe` | `issue` (issue ID), `use` (one issued name), `evidence`, `result`, `verdict` (`supports`, `contradicts`, `unresolved`) |
| `transfer` | `parent` (observation ID), `prospect` (new or existing open ID), `use` (one use object), `warrant`, `challenge`. Optional `roles` selects a subset of the previously issued source roles. Returned record is a new issue. When present, `later_different_verdicts` lists the most recent observation for each different verdict entered after the parent for that same issue/use, newest first, as of transfer. Each entry has an `observation` ID for resolving the evidence and its `verdict`. The receiving use still needs its own observation. |
| `catchup` | `parent` (known original observation ID). Optional `limit` (1–64, default 16), `scan_limit` (1–256, default 128). To continue, send the full returned `next` as the next spec to the same source and local file. |
| `show ID` | ID replaces spec path. Returns the frozen record. |
| `recover OWNER_SHA256` | Digest replaces spec path. Writes exact raw owner bytes to stdout. |

`sources` contains one to three `{role,path}` entries with distinct roles. For a native nomination supply the optional `identity` field and the issue's `nominations` ID. The companion checks the complete selected owner's digest against that exact nominee, including when a smaller window is issued. External sources omit `identity`. `uses` contains one to four `{name,decision,authority}` entries with distinct names. `partial`, source `path`, `authority` and `evidence` each accept a file path or `{path,start,end}` with zero-based UTF-8 byte offsets and an exclusive end. Paths resolve relative to the spec. Preserve decision-specific outcomes by addressing each observation to a single issued use. `reuse` checks an existing supporting observation for same-basis replay. `transfer` creates a new decision-specific test.

Federated form: `lookup {prospect,reader,manifest,manifest_sha256,limit?}` (default global limit 3, maximum 8). The manifest is a JSON object `{"shards":[{"name":"s00","library":"relative/library","index":"relative/prepared.sqlite","index_sha256":"...","scan_limit":1000,"max_bytes":8388608}]}`. Paths resolve beside the manifest; `max_bytes` is optional (native default 8 MiB). Each result in `bodies` has `shard`, `pin`, `title`; `coverage` includes `examined_bodies`, `matched_bodies`, `omitted_body_count`, `shards_consulted`, `matches_unissued`. `cost` summarizes native response and verified-index byte counts. `audit_sha256` recovers exact per-shard cost and coverage via `recover`. To pin a nominated source for issue add `identity` and `shard` to the source entry. All declared shards are consulted, or lookup fails.

For an incoming job with no previous observation ID, run `python -B recall.py STATE NEW_PROSPECT_ID [--limit 1..5]`. It uses the prospect's frozen query and searches observed investigations in this journal. Each candidate supplies `observation` for `show`/`transfer`, its prior `issue`, local decision/result/verdict, matched excerpt and exact source, evidence and authority pins. No observation is created or inherited by recall. The journal's disposable FTS5 index is maintained incrementally. See the [operating guide](README.md).


### Read a scoped history after a frozen observation

`python3 -B turn.py JOURNAL catchup SPEC.json` returns subsequent observations of **the parent observation’s original issue and named use**, in source-local recorded order. For a transferred issue use its `parent` observation ID. Each reference carries an observation ID, verdict and the digest of its evidence selection. Use `show ID` at the originating journal to acquire the observation and its selected evidence. The digest identifies the selected bytes; full owner recovery is separate. This query creates no records and requires no search index.

The first page fixes a local journal boundary. A response with `complete:false` contains `next` even if its observations list is empty. Both declared limits apply to every page; unrelated records consume the scan allowance. `records_scanned` and `record_body_bytes_scanned` count the forward walk, excluding fixed anchor/boundary lookups, SQLite pages and response encoding. The limits bound work per request. A sparse history can require many requests. A caller with sufficient source access can instead inspect its own journal directly. A new pull from the last acknowledged scoped observation can examine later appends.

The parent, cut and cursor must come from the same trusted append-only custody. Tokens bind the parent, local physical file identity, position and boundary-record identity; a restored or copied file needs a new pull. They are opaque consistency checks, not authorization or a signed digest of every intervening record. Journal positions and scan counts reveal aggregate activity. The exposing owner must authorize each recipient and protect the source against mutation, replacement and impersonation. The originating file and its contents must remain stable except for native appends; inode reuse or in-place history rewriting is outside the guarantee. A finished page series attests coverage through that cut, without granting receipt of the bodies, current truth or any decision for the receiving use.

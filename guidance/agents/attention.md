# Use attention feedback

Use feedback when several continuing questions, source changes, or wider alternatives need a reliable place to return. Keep a question's current use, relevant sources, useful treatment, and remaining participation together. Ordinary notes can serve this purpose; an available host can capture and return them.

## Turn a returned condition into useful work

| Returned condition | Useful action |
|---|---|
| A nominated item has no recorded treatment | Examine it if it matters now; otherwise explain the deferral and retain any actual duty. |
| Its question, use, or source basis changed | Determine which part of the earlier contribution still applies. Reconstruct the affected relationship and keep the original account as history. |
| A treatment contains an open question | If its contribution is selected or still owed, continue from the usable product; otherwise retain its reopening condition. |
| Named items were omitted from delivery or lie outside the selected view | Request the relevant items when the current contribution needs them. |
| A bound product changed | Inspect its current body where the claimed effect depends on it. |
| Previously treated items acquire a consequential joint use | Record that new relationship as its own question or revise the receiving use. |

A useful treatment is a conclusion, source comparison, changed artifact, operation, or specific request. Connect it to the items it actually addresses. A shared account can support several items through different parts of its contribution.

Use material already available in context. Recover a captured source when its exact earlier content matters; read the current source when the present operation needs that version. Keep the two occurrences identifiable.

## Use the available adapter

The shared native engine exposes `track` for nominated questions and `assess` or an assessment on `receive` for actual treatment. Its separate `feedback` operations own a prospective use and returned observation. Use the current engine help and operation contracts for their distinct inputs; recover retained context with `recover TURN --text` when that original body is needed.

The returned ordering identifies record conditions. Choose work by its contribution to the task. A considered item can remain open; a deferred item retains any duty still owed. At a consequential return, use [reselection](AGENTS.md) to decide whether further work serves the duty. A completed contribution may leave no selected next task.

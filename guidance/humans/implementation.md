# What is built and how to use it

The full release includes three initialized stores sharing one engine: research, novel and discovery. The walkthrough below uses research and novel. The focused operating package has a separate deployment and source selection. Reusable domains supply knowledge, payload schemas and explicitly invoked tools. Each store owns its current goal, records, artifacts and receiving history.

## Choose support by its contribution

| Needed contribution | Available means | What a participant still supplies |
| --- | --- | --- |
| Find and read relevant knowledge | Hash-bound source catalogues, complete-body reads and bounded discovery | A meaningful question, source selection and interpretation |
| Preserve current work and independent obligations | Versioned native records, goals, contexts and return custody | Whether the records adequately represent the owed work |
| Enforce a declared storage shape | Loaded domain schemas at the native write owner | A useful meaning and a sound schema for the task |
| Continue separate applications | Independent stores and reference-only deployments selecting one engine | Actual ownership and authorization of effects |
| Receive a finding from another instance | Exported record, pinned source observation and receiver account | Whether to adopt, investigate, repair or retain the affected work |
| Develop writing or an AI system | Reusable domain knowledge and operations | Actual construction and receiving judgment |
| Maintain broad, local and joint observations | Qualified measurement operators, a current field and persistent shared-use eligibility | Source meanings, adequate aggregation, actual receiving and a capable invocation host |

## Read the actual initialized state

Run from a package root that includes the named stores, with the supported Python environment:

```bash
python3 -B engine/runtime/manage_store.py --root stores/research status
python3 -B engine/runtime/manage_store.py --root stores/research show C1
python3 -B engine/runtime/manage_store.py --root stores/novel status
python3 -B engine/runtime/manage_store.py --root stores/novel show novel-current
```

Use `catalogue --query TEXT` to nominate a source and `catalogue ID --text` to read the selected complete body. The research catalogue includes full arguments and guidance, not merely an abstract. The novel catalogue includes its current manuscript and selected models alongside reusable writing knowledge. A catalogue entry or loaded file does not mean that a participant has read or understood it.

The [research entrance](../../stores/research/README.md) exposes the current field and its selected field-composition/signals question. The [novel entrance](../../stores/novel/README.md) exposes the current food-provision successor, its loaded artifact graph, actual models and receiving. Enter through `compose --record novel-artifact-composition` and a consequential relationship; the writing-domain operation supplies complete selected prose/account units and checks the current parent before preparation and adoption. Read the whole manuscript when the question needs whole receiving.

The novel has 110 available source identities and recoverable inherited accounts containing 155 scoped uses. The [current source account](../../stores/novel/work/source-account.json) owns acquisition and participant attribution; the [current signal field](../../stores/novel/work/models/signal-field.json) separately owns scoped observation, qualified nonuse and remaining work. Broad dependency and cadence measurements join actual selected prose receiving. The reader-encounter, sequence and care models retain their original source effects. Availability, inherited use, current acquisition, useful construction and accepted whole effect answer different questions. Loading a domain changes none of those semantic claims by itself.

The [measurement contract](../../domains/writing/operations/MEASURING-SIGNAL-FIELDS.md) states the actual units, roles, denominators and limits. Select which relationships belong to a factor before aggregating their chapter coordinates: source-use and observing relationships remain useful without becoming literary dependencies. The cadence operation can reuse eligible unchanged unit features from an explicitly trusted prior while checking all current bound owners and recomputing totals and joint comparisons. That saves selected extraction work; it does not remove semantic receiving or establish that changed reader context is harmless. The [continuing host](../../engine/host/SIGNAL-FIELD.md) preserves eligibility and recoverable attempts across changes and restart. An active capable session or installed callback supplies actual semantic work. Current service and coverage counts do not certify whole-book quality or unattended model execution.

The received reader-encounter comparison illustrates useful retained work. Moving an existing explanation earlier offers earlier anticipation and a tighter later transition; receiving still selects the current placement beside its concrete referents. The joined bookend relation constrains later compression without deciding that placement. The model narrows necessity and continuous-signal claims rather than forcing a prose or engine change. This is informed selected-unit receiving, not a measured first-reader preference.

## Keep owners and current work distinguishable

| Body | Canonical owner |
| --- | --- |
| Executable implementation and native APIs | `engine/` |
| Optional shared adapters with distinct contracts | `engine/companion_representation/`, `engine/host/` |
| Reusable theory, writing knowledge and system-development knowledge | `domains/` |
| Human explanations and agent operating guidance | `guidance/` |
| Current research decisions and received interpretations | `stores/research/` |
| Current novel, source account, models and writing commission | `stores/novel/` |
| Selection of an engine and instance | `deployments/` reference descriptors |

A deployment refers to the shared engine and one instance. It does not copy an engine for each edition. Source records bind complete canonical bodies by path, digest and size. Store bindings are portable within the package. Each instance has its own identity and record revisions; it cannot silently acquire another instance's authority by copying a status field.

The three writing commission duties have authoritative records in the novel instance. The two original-history duties belong to research. Research receives pinned observations of the three novel duties so its open-work view exposes all five without independently mutable duplicate statuses. A later source change requires deliberate receiving and reconciliation.

## Construct, receive and revise

Begin with a concrete contribution and its receiver. Use the current method to project the intended result forward and reconstruct the material and participation it needs. Develop partial wholes where they expose consequential interaction. A new representation is useful when it can change the work; an attractive wrapper around a prescribed answer is insufficient evidence of exploration.

Use ordinary native records to retain meaningful questions, models or findings. The selected domain governs the declared payload kind; unknown semantic truth is not supplied by validation. `put --record FILE --expected REVISION` checks expected revision, with zero for creation. A native context captures the selected source, record and target basis. A real return can be received and a justified proposal adopted through its actual owner. These checks preserve custody and change authority; they do not grade the artifact automatically.

For a received finding, distinguish a demonstrated producer defect, a source interpretation, a new question, a scoped creative preference and an adequate retained result. Map a defect to the means that caused it, change those means, and receive the affected new production against that failure class. A report edit is not a generating repair. A later source account cannot have caused earlier prose.

Cross-instance transfer preserves the original instance, record ID, revision and digest. The receiving instance records its own account and may open feedback or revise its own interpretation. Receipt, acceptance and useful downstream effect are separate observations. No permanent central semantic arbiter or universal task graph is implied.

## Acquire only the assurance the task needs

Exact bytes can establish which source was acquired. They do not establish its current authority, complete original-event coverage or present usefulness. A retained accepted body can remain adequate at one scope while a changed use needs a different source relationship. Bounded discovery can nominate a useful peer without proving that omitted matches are irrelevant.

The D12 incident instrument remains sealed. Its registered metadata is available, but its corpus and answer keys are not automatically exposed or indexed for reading. Missing eight world-source bodies and inherited novel-generation history remain missing; a new adequate construction is not an original historical replay.

## Maintain enough useful state

Keep current claims, obligations, sources and operative artifacts together with evidence that can materially support their next use. Retain an exact occurrence when a particular duty requires it. Otherwise a sufficient current account, new observation or adequate reconstruction can replace a full trace. Do not create an unbounded history simply because the storage interface permits it.

The writing source projector keeps one unchanged attributed historical acquisition witness per logical identity by default, the complete current occurrence, and additional older claims selected for a specific continuing use. This preserves coverage without accumulating every agent’s reading history. A historical logical identity does not certify the current source edition or transfer the old participant’s reading to another person. Exact older actor/body evidence remains selectable when needed. The current signal-field account uses this same repaired producer; its acquisition boundary comes from actual complete-body declarations. Received accounts, numerical processing and host service do not establish all-110 efficacy.

An unknown external effect remains unknown until its actual owner observation or honored idempotency relationship settles it. Moving files, switching a descriptor or writing a new account does not authorize repeating the effect. Use the original recovery route or a fresh authorized receiving occasion.

## Claim limits

The engine supplies cooperative local execution, storage and selected guards. Domains supply explicit schemas and knowledge; models and humans supply interpretation. Local verification does not establish hostile isolation, arbitrary crash durability, independent human artistic preference, general evaluator accuracy or complete economy. The [research conclusions](../../stores/research/work/CONCLUSIONS.md) and [frontier](../../stores/research/work/FRONTIERS.md) preserve those broader qualifications.

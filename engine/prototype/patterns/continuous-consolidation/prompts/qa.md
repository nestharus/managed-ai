# QA contribution

You obtain and interpret the verification needed by the current candidate and receiving promise. Use the [operating contract](../README.md). Acquire the exact candidate/branch identity, current required checks and the question each check is meant to resolve.

Use an existing suitable PR or verification target. Create or change one only within the authority supplied for this work. Retain actual test/CI invocation identities and returned outcomes. Coalesce compatible verification requests for the same relevant candidate; avoid launching equivalent jobs merely because several reports arrived.

Recover an uncertain provider/job outcome before deciding whether another invocation is needed. A retry of a catalogue route is not permission to repeat the provider effect. Keep the verification result tied to the tested candidate and relevant conditions; later changes may require a new assessment or selected rerun.

Interpret failures. Route a concrete repair to construction, an expanded/shared duty to work coordination, or an integration condition to branch coordination. Keep independent checks and useful work moving where their conditions remain adequate. A reported test success does not resolve a semantic contradiction outside its coverage.

Return the actual tested identity, outcomes, evidence, unresolved failures and the receiving conclusion those results support. Route an accepted candidate onward only under the current work policy. Preserve historical results when the candidate changes rather than relabeling them as fresh verification.

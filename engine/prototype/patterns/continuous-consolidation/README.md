# Continuous consolidation: operating pack

Use this pack when agents receive overlapping work, prepare proposals in parallel, and need to revise their interpretation while useful work continues. It provides role prompts and an illustrative inventory convention using the existing collective-work adapter. It contains no new scheduler, model client or storage engine.

**Current status:** reusable guidance, exercised in a constructed local title-provenance receiving use with actual model returns and the existing collective adapter. Later provenance changed the accepted work while both original reports and an independent prepared contribution remained available. The demonstration establishes its particular interpretation and local admission behavior; production capacity and installation into another agent host remain separate. No external agent system has been changed by these files.

## Operating shape

Keep original reports recoverable. Store one current consolidation scope as an ordinary revisioned target whose body contains grouping and route intents. Prepare semantic proposals outside admission. The owner accepts a current interpretation using `capture`, `propose` and `publish`; an independent scope uses another target. A receiving work or effect target captures whichever accepted scope it actually consumes.

When later evidence changes a grouping, revise its effective consumers. Keep adequate partial work, retain the original reports, and reconsider affected old actions under the new basis. Keep route delivery and downstream effect completion separately observable.

The host must actually supply the operations the prompts use:

| Host relationship | Required behavior when this use consumes it |
|---|---|
| Receipt and recovery | Retain the packet or report before acknowledging durable receipt; recover the actual outcome of an uncertain receipt |
| Current source and target reading | Return the complete selected unit and its actual identity/revision |
| Guarded acceptance | Check the relevant current conditions together with publication; preserve the returned artifact when admission refuses |
| Invocation and returns | Launch permitted work, retain actual child returns, and make pending work discoverable after interruption |
| Effect ownership | Preserve authorization, stable intended-effect identity and actual outcome; recover uncertain effects through their owner |

The collective adapter supplies one local artifact-scoped acceptance arrangement, exact command receipts, retained proposals, notices and optional short fenced claims. Its body JSON remains open. It does not interpret duplicates, invoke agents, guarantee service capacity, provide cross-target atomic publication, or execute external effects. A host that already supplies adequate receipt and acceptance can use the pattern with its existing inventory.

## Map the pattern to the existing adapter

| Contribution | Existing operation and ordinary data |
|---|---|
| Retain a report | Create a report artifact with its occurrence identity and complete useful body; use the exact command receipt for delivery recovery |
| Establish a current scope | Create an owner-controlled scope target and the actual `reconsider_from` policy needed for its receiving duty |
| Prepare a revision | Capture the scope and sufficient current sources; let a capable participant return the proposed body; retain it with `propose` |
| Accept grouping and routes | Publish the complete scope body with its actual account, required treatments and applicable claim token |
| Make a revision consequential to work | The receiving work target captures the accepted scope as a source; its later publication checks that basis |
| Supply a new finding | Offer the actual consequence and source pins to the target that must consider it |
| Resume a route | Read the accepted scope/change record, deliver its intent under the host contract, and retain the actual receiving outcome |

An offer pending at the scope target does not automatically block another work target that merely reads the scope as a source. Publishing a revised scope makes that captured source stale. If the promised effect must wait as soon as reconsideration is pending, give that effect target the actual required offer or a represented pending-condition source that its admission checks. Do not assume transitive invalidation that the host has not implemented.

These roles can share a context or be delegated. Review, QA and branch are available receiving routes, not an obligatory pipeline for every artifact. Combine compatible packets into one meaningful child contribution; do not spawn a child merely because another packet arrived.

Use [inventory.md](inventory.md) to adapt the current inventory. Its complete fenced JSON example is explanatory data, not a request to submit unchanged. It includes no fabricated source hashes or acceptance receipts. Actual pins come from the host's returned current reads and publications.

## Adaptation boundary

Bind the prompts to the existing packet receipt, inventory read, proposal retention, publication, invocation and effect-recovery operations. Preserve the host's actual authority and restart contract. A live-session map can be an advisory convenience; current acceptance must not depend solely on a volatile “integrator running” flag.

Use the simplest arrangement that meets the receiving promise. A single windowed integration context can be adequate. Several scoped interpretation workers and one short shared admission owner can remove unnecessary semantic serialization. Several admission owners need an actual treatment of shared conditions. Cross-scope effect exclusion requires a represented joint owner or atomic predicate; independently current row hashes are insufficient.

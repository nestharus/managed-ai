# From an outside notice to the first shared direction

An editor is preparing an evening pickup direction. Which door should the courier use? A venue's notice informs the editor. Only the venue's board can admit the first shared direction under the current grant. The board is already a disclosure, even if a later pickup is refused.

Run from this example directory, giving the path to the extracted compact. Python 3.11+ and a POSIX host suffice. The example uses the actual release commands and a small SQLite teaching host. For a retained run, append `--work /path/to/new-directory` outside the compact.

```sh
python3 -B bridge.py /path/to/G60-system-use
```

| Participant | What it owns | What to inspect |
|---|---|---|
| Tour organizer | The requested commission, intended reader and contributing editor | The venue registers that job once with its currentness policy. A commission by itself cannot place a card on the board. |
| Venue office | Numbered editions of each site's notice and the active door | `venue.py` exposes a dated export. A changed notice advances its edition. |
| Scout | A scoped interpretation and the selected source bytes in the collective intake database | `evidence.py record` then `show` returns the scout's occurrence. Its account names the exact venue edition. |
| Editor | The native source head, private candidate, disclosure permission and feedback use | `bridge.py: import_reading` copies the selected bytes to a new edition-specific basis and calls native `put` with source owner/edition, collective store/owner/pin and reading. Native feedback uses the new pin. |
| Board owner | First shared insert, including the receiving job and audience | `Venue.share` checks current permission for every new disclosure. A historical citation checks its exact edition. A live direction checks the current edition inside the transaction that creates the board row. |
| Courier | Use of the one door actually shown on its own board | `Venue.collect` reads the issued card, visits its door and records the parcel handover once if the door serves this site. |

**Follow the break in the forecast.** On the first pass the venue confirms that the garden door is active and the private native review records that observation. The venue then moves evening pickup to the canal door. The local source head and earlier captured bytes are unchanged, so native inspection still reports `review` and an empty stale list. Checking a new owner export against the original collective reading detects the change. The live publication itself holds the old draft even if a caller skips that check. The archived citation remains inspectable, a withdrawal on an unchanged edition prevents disclosure to the excluded reader, and an independent venue completes its own job. A remote live commission with no joint admission capability stays private.

**Carry the failure back.** The editor records the actual refusal in native feedback, obtains a fresh venue export and reissues the new reading at revision 2 of the native source. Revising the forecast preserves the earlier adverse return. The editor supplies a new card. Its board reader receives one direction, and pickup at that door creates one handover. Repeating either successful operation creates no second occurrence. The new receiving evidence supports resolution of that earlier failed use. The first forecast can still be inspected at its own revision.

A current authorization and correct edition still admit a bad interpretation. A second reader receives a deliberately misread current notice and goes to the garden door. Its board insertion succeeds and its pickup fails. The host's admission and pickup are independently exercised operations.

**Adapt at the authority.** The host defines which export source an incoming locator refers to and who may read each store. The example uses a trusted local process and co-locates canonical state and the first public writer in one venue service. For another service, use its own authorized conditional operation or keep the live-dependent effect pending. A pre-write poll in another database cannot supply that guarantee. The fixture supplies the interpretations, the teaching door and the disclosure policy. A person, independent provider and general semantic evaluator were not exercised.

The editor calls `approve(editor, job, reader, draft)` for a particular disclosure. The venue records the complete JSON draft’s fingerprint with the fixed commission, contributor and audience. Approving the same tuple again returns the original receipt, including its withdrawal status. The board transaction compares the submitted draft to this grant, checks the source edition under the job’s policy and inserts the public card. A change to the door, an extra audience label, or reuse of the receipt on another commission is held. Here the same private reading also supports an old-edition citation for an archivist who has a separate approval.

The fixture treats principal arguments to commission, approve, withdraw and read as identities supplied by trusted local entry points. Only a trusted venue writes its tables. Grant IDs are database lookups. A real host must authenticate the participants, restrict private stores and authorize those entry points. In particular the publisher cannot act as the contributor or choose the audience for an existing commission. A withdrawal and publication serialize on the same SQLite writer. Withdrawal that commits first prevents publication. If publication committed first, the reader can still see that card, and a later retry returns `disclosure withdrawn`. Repeating a successful publication under its active grant returns `already shared`.

G60 record hashes include occurrence data and can differ on replay. The printed checks compare identities within that run.

## Record progress on one combined use

From the same directory run `python3 -B partial.py /path/to/G60-system-use`. An offline recipient unpacks and runs four revisions of a carton calculator. The initial package lacks a capacity file and accepts negative orders. Adding the file repairs the six-item order. The first attempt to pack seven items uncovers a rounding defect. The mixed return retires the missing-file duty, keeps the negative-order duty, and opens the rounding duty. Fixing the rounding retires that duty without inventing another fault. Acceptance still refuses. Only a subsequent receiving run that exercises the corrected utility reaches review and owner acceptance.

Use separate scopes when different recipients can accept their jobs independently. Here one recipient owes one usable offline utility. Select `progress` for a measured partial repair while another duty remains. Select `work` or `hold` when the same observation also brings a new adverse consequence. In either case, identify exactly which previous return each resolution addresses. The observation records the current candidate and its exercised role. The owner remains responsible for what the observation justifies.
